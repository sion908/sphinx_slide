Jujutsuって？
----------------------------------------------------------------------

Gitと連携して使える、別のバージョン管理システム

.. revealjs-fragments::

    * コマンド名は ``jj``
    * Gitリポジトリをバックエンドにできる
    * GitHubを使うチームでも、自分だけjjで作業できる

作業中の状態も履歴にある
----------------------------------------------------------------------

jjでは、作業コピーがコミットとして扱われます

.. code-block:: text

   $ jj log
   @  zuknkrqq sion908@example.com  99d8bddc
   │  hello jj
   ◆  zzzzzzzz root() 00000000

.. revealjs-fragments::

    * ``@`` が、いま編集している作業コピー
    * jjコマンド実行時に作業コピーの変更がスナップショットされる
    * 「コミットする前だから何も残っていない」が起きにくい

操作そのものにも履歴がある
----------------------------------------------------------------------

.. code-block:: text

   $ jj op log -n 3
   @  14d44624dfa0  now  new empty commit
   ○  4c79e66c77e9  now  snapshot working copy
   ○  288fea96c31b  now  describe commit

.. revealjs-fragments::

    * ファイルの履歴だけではない
    * jjに対して何をしたかも見える
    * 間違えた操作を追いやすい

間違えたら ``jj undo``
----------------------------------------------------------------------

.. code-block:: bash

   $ jj new
   # あ、まだ新しい作業を始めるつもりではなかった
   $ jj undo

.. revealjs-fragments::

    * 直前の操作を戻せる
    * 操作の履歴は ``jj op log`` で確認できる
    * 試行錯誤するときの心理的コストが下がる

Gitのチームで自分だけjjを使える？
----------------------------------------------------------------------

使えます。

.. revealjs-fragments::

    * チームはこれまでどおりGitとGitHubを使う
    * 自分のローカル作業だけjjにする
    * pushしたコミットは、他の人には通常のGitコミットとして見える
    * ローカルでGitとjjの変更操作を混ぜすぎないのが安全

実際には、こういう作業が多い
----------------------------------------------------------------------

**PRを出して、レビューで修正する**

.. container:: flex

    .. container:: size-1

        **PRを出す**

        .. code-block:: bash

           jj git fetch
           jj new main -m "feat: add login"
           # ファイルを編集
           jj bookmark create feat/login
           jj git push -b feat/login

    .. container:: size-1

        **レビューで直す**

        .. code-block:: bash

           jj edit feat/login
           # ファイルを修正
           jj git push

.. revealjs-fragments::

    * ``git add`` は不要
    * bookmarkは、修正したコミットに追従する
    * GitHub上では、いつものPRとして扱える
